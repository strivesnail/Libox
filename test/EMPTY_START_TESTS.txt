Empty-start insertion (2026-11-09)

Both indexes support constructor-only integer-key insertion without loading a
configuration. The first insertion creates one empty segment starting at that
key, with up to 64 keys of half-open coverage, then inserts the value. Concurrent
first insertions and subsequent directory growth use the structural writer gate.
Keys outside existing coverage add adjacent ranges with geometrically growing
width. Large untouched tails remain sparse rather than allocating dense buckets.
Empty lookups return not found. No-config bulk insertion keeps splitting enabled.

Limitations: numeric_limits<Key>::max() cannot be inserted because the existing
half-open representation requires a representable exclusive upper bound; insertion
throws out_of_range. Floating-point keys still require configured ranges.
Structural changes use the existing blocking quiescence gate.

Validation:
  python3 test/run_concurrency_checks.py
23 cases passed in each repository with ASan/UBSan (leak checking disabled for
existing allocation ownership); includes simultaneous first insertions, signed
integer extremes, no-config bulk insertion, and deep concurrent splits.
Both release benchmarks built successfully.

Dataset validation: MSR Cambridge web_2, 1,321,270 unique raw byte offsets.
This is not the paper's exact preprocessed dataset. Constructor-only insertion,
no config or preload; sorted/reverse/random order, 1/24 threads, both indexes:
12/12 passed with all inserted key/value pairs checked.

Performance: same dataset, RO/BAL/WO, 1/4/24 threads, seeds 42/43/44;
108/108 before/after runs passed. Baselines are the immediately preceding main
commits, RiB-tree c503e40 and Libox 94aefe4, not pristine upstream.
Throughput median change: RiB-tree -0.96% to +3.52%; Libox -4.57% to +1.67%.
Three short repetitions are preliminary and do not establish equivalence.
